Release safety is more than a green build

Schema and reporting changes have explicit review points because application rollback alone cannot undo a data migration.

Release
■
Controlled migrations CI generates an idempotent EF SQL script for review. Production migrations run as a controlled database step, not concurrently from multiple API replicas.
■
Backward compatibility Prefer expand/migrate/contract changes. Add nullable columns first, deploy code that reads both shapes, and remove old columns in a later release.
■
Backup before schema change Always take a SQL Server backup before applying a schema change. Use database restore for data-loss rollback.
■
Rollback boundaries Keep the previous image tag and report definitions for rollback. Do not assume an older image reverses the database schema.
